## 动态天气系统（V3）

天气为游戏内**程序化模拟**，不依赖现实天气 API，五种预设分别为：

| 天气 | 视觉和飞行反馈 |
| --- | --- |
| ☀ 晴朗 | 明亮的天空、柔和海面、微风 |
| ☁ 多云 | 云层变密，天空、海面与阳光逐渐变灰 |
| ☂ 小雨 | 倾斜雨丝、细小海面水纹、潮湿空气感 |
| ⚡ 暴风雨 | 深色乌云、更起伏的海浪、闪电、阵风侧漂 |
| ≈ 海雾 | 降低远景能见度，轻风，无雨丝 |

点右上角的天气按钮可从天气菜单直接选择预设，按 \`T\` 顺序切换天气；切换后默认进入手动模式。菜单中的“自动变化”可重新开启自动轮换，约每 60–80 秒改变一次天气。风只影响**自由飞行**，不会改变 E 辅助降落/F 起飞的预设轨迹。

单文件实现位于 \`docs/islebound/index.html\`，实现 \`createWeatherSystem()\`、\`update()\`、\`applyWind()\` 和 \`gustRoll()\`。天气状态亦暴露在 \`window.__ISLEBOUND_DEBUG.weather\`，例如在浏览器开发者工具输入 \`window.__ISLEBOUND_DEBUG.weather.select('storm')\` 即可切换到暴风雨，\`select('fog')\` 切换海雾。

发布前可运行（仅需 Node.js）：

\`\`\`bash
node docs/islebound/tests/weather-regression.mjs
\`\`\`

**人工浏览器回归：** 启动游戏 → T 键切换五种天气 → 等待天气逐渐过渡 → 暴风雨中观察雨丝/海浪/闪电/侧风 → E 降落、F 起飞 → 查看移动端天气按钮和小地图 → 开启自动模式观察随时间变天。

当前上线版本标记：\`2026-11-17-weather-v3-color-safe-fog\`。更新博客时继续替换相同的 \`index.html\`，发布地址无需变化。


### V3：修复雨天/暴风雨/海雾导致的岛屿“白模”

原来的 `THREE.FogExp2` 在暴风雨中密度可达到约 `0.00516`。距离相机 300 单位处，雾效会替换约 91% 的表面颜色；而海面采用独立 ShaderMaterial，没有同等的内建雾混合，所以会出现“海洋仍然有色、整座岛却苍白”的对比。

改为 `THREE.Fog` 线性距离雾，天气切换时对雾的起止距离做平滑过渡。海雾仍能遮挡远处岛屿，但不会在接近机场时把近处树木、地表和建筑全部洗白：

| 天气 | 雾开始距离 | 完全雾化距离 |
| --- | ---: | ---: |
| 晴朗 | 850 | 2600 |
| 多云 | 560 | 1950 |
| 小雨 | 410 | 1350 |
| 暴风雨 | 310 | 1050 |
| 海雾 | 165 | 710 |

暴风雨下，300 单位内保留全部材质色（不受雾叠色影响），在 500 单位处的雾混合约 26%；海雾下 250 单位处约混合 16%，600 单位处约混合 80%。这些是距离雾公式的测试值，不是实机像素统计。保留之前的天空云纹、云带、雨丝、雷电与风。

回归测试：`node docs/islebound/tests/weather-regression.mjs`，新增雾混合范围断言，确保岛屿近景颜色不再被天气雾效吞没。


## 岛屿标签稳定性修复（2026-11-17）

**问题根因：** 之前的 `updateLabels()` 与 `updateHUD()/drawMap()` 一起被 `uiWait>.08` 限流，因此标签投影位置约每 80ms 才更新一次（12.5Hz），而相机每帧都在移动，标签出现明显跳帧。标签还在 `dist>430`、屏幕坐标越界时直接隐藏，再叠加 CSS `transition:opacity .25s`，造成闪烁和不一致的出现节奏。

**修复：** 新的 `updateSceneLabels(dt)` 在 `updateCamera()` 后、每帧 `renderer.render()` 前执行，位置与摄像机同一帧更新。标签坐标使用 `translate3d()` 组合变换（不再低频修改 `left/top`），使用时间步长相关的指数衰减对透明度渐隐/渐现，且对视口边缘和最大可见距离分别使用平滑过渡；同时移除 CSS 对透明度的二次动画。机场降落提示保留原有 HUD 更新频率，不受影响。

**回归：** `node docs/islebound/tests/label-regression.mjs` 会检查标签与相机在同一帧更新，并模拟 120 帧连续相机移动、渐显和切换近景视角隐藏标签。天气、飞机、降落逻辑均保持原状。

本次版本标记：`2026-11-17-label-stability-v1`。固定博客入口仍为 `/PhotoGallery/islebound/`。


## 狗狗岛与猫猫岛景观贴合修复（2026-11-17）

针对实机截图：

- **狗狗岛房屋后面的大型白色“烟囱”**：其实是骨头主题拱门，原坐标 `(-6,-36)` 与小屋 `(-10,-36)` 距离过近，产生穿插。将骨头门改放到 `(31,-70)` 的独立空地（横向也避开房屋与跑道常用视线），为小屋增加按屋顶坡度嵌入的小烟囱，同时把骨头门位置加入树木避让。
- **猫猫岛跑道旁悬空的灯笼**：原串灯使用与绳索轨迹无关的 `sin()` 坐标，部分灯笼漂浮且灯串经过跑道。改为从同一条 `CatmullRomCurve3` 中采样灯笼坐标，用短杆连接绳索，并将整条灯串移到鱼市街道，端点立杆按实际地形高度落地。
- **沿海一排小灯**：改为有可见柱身、灯帽和底部嵌入地形的独立灯杆组；此前杆身半径仅 0.1，远处几乎看不见，灯泡视觉上像悬浮小蛋。
- **猫猫岛木板与石片**：原跑道旁木板基准为 `Y=14`、地面约 `Y=13.05`，下沿高于地表。降低木板、海岸石片和鱼市地砖，让底部适度埋入草地；装饰小猫添加触地前爪，猫爬柱上的小猫也摆到平台顶端。

所有修改沿用现有 `groundIslandDecor()` 真实三角形高度采样和 `instanceStaticIsland()` 批处理，不改变四岛地图、飞行、天气、降落或标签系统。

回归：`node docs/islebound/tests/prop-grounding-regression.mjs`，检查骨头门与房屋、跑道之间的净空，猫猫岛铺装下沿、灯泡与线缆连接、路灯接地和猫爪位置。

版本标记：`2026-11-17-prop-grounding-v2`。

## 架构

单文件静态网页；Three.js 通过 CDN 加载，场景在浏览器中程序化生成，无服务器端功能。岛屿配置保留在游戏的 `ISLANDS` 数组中，可扩展第五座及更多岛屿。
